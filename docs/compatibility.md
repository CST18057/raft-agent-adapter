# Compatibility and validation

Version 0.3.0 adds DeepSeek Harness (`backend: "dsh"`) alongside Devin. The CodeBuddy Code backend (`backend: "codebuddy"`) is unreleased and listed in the same tables. Protocol behavior depends on the installed Raft and backend versions. Please include all three versions when reporting a regression.

## Known limitations

- The runtime selector remains **Grok Build**. A real Grok installation cannot directly share the local `grok` slot.
- **Authentication model.** The standalone Devin CLI uses its local `devin setup` login inside `devin acp`; sign in before relying on the model list. A Devin Desktop-bundled binary instead requires the ACP host to call `authenticate` — the adapter forwards such calls, but Raft's Grok slot never sends them, so prefer the standalone install. Without login, `session/new` works but the model list is empty.
- Raft's Grok account/usage widget may show **needs attention**. Grok-specific account reporting is not implemented; use the official Devin CLI to check login and account status.
- Raft's Grok login/update actions are not backend management commands. Manage Devin through its official CLI; manage dsh providers and keys via `dsh web` or `~/.dsh` files.
- One backend per adapter installation — the `grok` slot resolves to a single executable. Two Raft agents cannot run different backends through one install concurrently.
- Switching `backend` after use: refresh Raft's model list and re-select a prefixed model; the other backend's model/session IDs are rejected explicitly. Raft does not detect the swap — the adapter's error messages are the reset signal.
- dsh specifics: no mid-turn interjections (queued and sent as the next prompt); no `session/delete` (close leaves the session listed); `initialize` waits for the dsh kernel and primed session, so a slow cold start can exceed Raft's ~15 s model-detection window. The cold-start time has not been measured. `npm run models:refresh` also leaves one listed session per run.
- Standing instructions are forwarded as a marked first-prompt block, not a native system-prompt replacement. They are sent again after a resume.
- Raft's Grok transcript locator does not find Devin's native transcripts. A handoff may contain identity only; complete transcript export/migration is not provided.
- Same-machine session loading was tested. Cross-computer transfer is not established by that test.
- Model lists and thinking options come from Devin. Refresh the local catalog after an update. Raft's supported vocabulary may omit native values such as `none`.
- Future changes to Raft's discovery, Grok extensions, or Devin ACP may require an adapter update.
- Native permission prompts are forwarded; this adapter does not provide an execution sandbox or change Devin's tool permissions.
- CodeBuddy Code: sign-in must already exist (`codebuddy` login or `CODEBUDDY_API_KEY`). The adapter never forwards `authenticate` to it, because that login logs out an existing session first.
- CodeBuddy Code has no `session/close`, `session/delete` or `session/list`. Closing a session only forgets it in the adapter, and every `session/new` (including the probe session used for model discovery) stays under `~/.codebuddy/projects/`.
- CodeBuddy Code's `session/load` succeeds for unknown IDs with a blank session, which would stop Raft's automatic fresh-session recovery. The adapter therefore records the sessions it creates (`.local/codebuddy-sessions/`) and answers `session not found` for any other ID before CodeBuddy sees it. Sessions created directly in the CodeBuddy terminal UI are not resumable through Raft as a result. Observed live: after a primed session file was deleted, the next adapter start resumed the stored ID and recreated it as a blank session; the record does not detect file deletion. Deleting `.local/` (or using a fresh checkout without it) also forgets the record, so earlier sessions then answer `session not found`.
- Mid-turn: a second `session/prompt` sent during an active turn is queued and runs after the first turn, but its response returns `end_turn` immediately, before any reply exists. The adapter therefore defers interjections (`midTurn: false`) and sends each one as a follow-up prompt, keeping the Raft turn open until it has run (`queuesPrompts`). Live runs showed the follow-up's reply can also stream a few milliseconds after the turn's response — ACP does not guarantee all of a prompt's `session/update` notifications precede its response.
- CodeBuddy Code sessions are opened with permission mode `fullAccess`, applied through `session/set_config_option` (`mode`) on every session open — a true full pass including dangerous-command checks, matching the posture Raft gives Codex (`approvalPolicy: "never"`, `sandbox_mode: "danger-full-access"`). Explicit `deny` rules still apply. Its other modes (`default`, `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`) are not exposed by the adapter; if the `mode` option is missing the adapter logs a warning and continues. A `--permission-mode` launch flag also exists, but unknown CLI options are fatal, so the adapter does not rely on it.
- CodeBuddy Code releases often: 2.147.0 and 2.179.3 differ in model count and capability flags. Refresh the catalog and rerun the handshake after each upgrade.
- CodeBuddy Code reports token usage per request in `usage_update` notifications, not in the prompt result. The adapter forwards those notifications unchanged and sums each request's usage into the prompt's `_meta.usage` in ACP's usage shape. Input, output and total tokens are mapped; cache and reasoning counts are not reported separately; on the checked requests, cache hits were part of the prompt tokens, and reasoning tokens are assumed to be part of the completion tokens. Verified live: the mapped result equals the deduplicated sum of the per-request updates. Raft's reading of the field is unverified. Its `_codebuddy.ai/*`, `config_option_update`, `current_mode_update` and `session_info_update` notifications also reach Raft unchanged; whether Raft ignores them is unverified.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Grok Build missing from inventory | Install the adapter (`platform/linux/install.sh` or `platform\windows\Install.ps1`), confirm `grok --version` runs, verify `~/.local/bin/grok` (POSIX fallback) or the user PATH entry, then rescan runtimes or restart the Computer |
| `runtime_not_authenticated` in Raft | Devin ACP rejected the launch: run `devin setup` on the standalone CLI install, or use an ACP host that calls `authenticate`. dsh never requires `authenticate` |
| CodeBuddy `runtime_not_authenticated` | Sign in once with `codebuddy` on this computer, or set `CODEBUDDY_API_KEY` for the process that starts Raft. The adapter does not call `authenticate` for CodeBuddy |
| Model rejected as "belongs to a different adapter backend" | The stored Raft model ID predates a backend switch — refresh Raft's model list and re-select, or revert `backend` |
| dsh agent stalls on first launch | `dsh acp` cold start is slow; verify `dsh` works standalone and that `~/.dsh` providers are configured |
| Old model list or no Max option | Re-run `models:refresh` (`platform/linux/refresh-models.sh`, `platform\windows\Refresh-Models.ps1`), then refresh the model list in Raft; a workspace Scan is unrelated |
| Configuration / handshake failure | Run `platform/linux/test-adapter.sh` or `platform\windows\Test-Adapter.ps1`; confirm official Devin login, configured executable, connectivity, and the supported CLI version |
| Invalid reasoning effort | Select one of the native choices; SWE-2 currently offers Medium, High, Max |
| Proxy connection failure | Ensure the configured local proxy is running and the Computer process has the intended configuration/environment |
| Build cannot overwrite launcher | Stop agents using this checkout before rebuilding |
| Node executable no longer exists | Reinstall/select Node 22+, rebuild (`build.sh` / `Build.ps1`), and restart the agents |
| `grok` on PATH resolves elsewhere | Another `grok` earlier in PATH shadows `~/.local/bin/grok`; remove it with that checkout's uninstall script, then reinstall |

Include sanitized errors and versions in an issue. Do not attach account files, raw transcripts, or full environment/PATH dumps.
